2 ЗАВДАННЯ
     
Необхідно розробити front-end частину програмної системи  для платформи керування доступом «Smart Lock»

     
     3 ОПИС ВИКОНАНОЇ РОБОТИ
       
     Smart Lock являє собою сучасну систему контролю та управління доступом, призначену для керування електронними замками, моніторингу доступу і ведення журналу подій безпеки.
     Основною метою платформи є забезпечення надійного та автоматизованого доступу до приміщень, виявлення потенційних загроз на основі аналізу даних від IoT-пристроїв (Див. Дод Б. Рис. 4), а також гнучке керування правами доступу відповідно до ролей користувачів (Див. Дод Б. Рис. 2).
     Апаратний рівень системи представлений бездротовими вузлами на базі мікроконтролерів ESP32. Серверну інфраструктуру реалізовано на платформі Node.js.
     Для закладання надійного фундаменту архітектури фронтенд-додатка було використано генеративні моделі ШІ з подальшим глибоким рефакторингом, ручною оптимізацією та адаптацією під реляційну схему даних PostgreSQL (Див. Дод Б. Рис. 1).
     Інструмент ШІ: Google Gemini 1.5 Pro
     Ціль використання: Отримання рекомендацій щодо початкового проєктування клієнтської частини системи, формування базової архітектури вебзастосунку, організації навігації між сторінками, керування станом застосунку та побудови механізму взаємодії з серверною частиною через REST API.
     Початковий промпт (Prompt): "Propose an architecture for a web application that manages access control devices and smart locks. Describe the structure of a React-based SPA, role separation between regular users and administrators, state management strategy, API communication layer with JWT authentication, routing organization, and recommended user interfaces for monitoring devices, managing users, viewing access history, and controlling locks remotely." 
     Внесок автора: На основі отриманих рекомендацій було самостійно розроблено архітектуру вебзастосунку Smart Lock, налаштовано маршрутизацію між сторінками, реалізовано систему розмежування доступу за ролями, створено модулі керування станом застосунку та реалізовано інтеграцію з серверним API. Також автором було розроблено інтерфейси адміністрування, журналювання подій безпеки та віддаленого керування замками з урахуванням особливостей предметної області. 
     У клієнтській частині системи Smart Lock реалізовано SPA (Single Page Application) на базі React, що забезпечує динамічну навігацію без перезавантаження сторінок та модульну архітектуру застосунку (Див. Дод Б. Рис. 3). Основою запуску застосунку є точка входу, у якій ініціалізується React-додаток, підключається маршрутизація та глобальні провайдери:
1. ReactDOM.createRoot(document.getElementById('root')!).render(
2.   <React.StrictMode>
3.     <BrowserRouter>
4.       <AuthProvider>
5.         <App />
6.       </AuthProvider>
7.     </BrowserRouter>
8.   </React.StrictMode>,
9. );
     
     Дана структура забезпечує підключення клієнтської маршрутизації, глобального контексту автентифікації та основного компоненту застосунку. Для управління станом автентифікації використовується контекст AuthContext, який дозволяє централізовано зберігати інформацію про користувача, токен доступу та стан сесії:
1. const AuthContext = createContext<AuthContextType | undefined>(undefined);
2. 
3. export const AuthProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
4.   const [user, setUser] = useState<User | null>(null);
5.   const [token, setToken] = useState<string | null>(null);
6.   const [isLoading, setIsLoading] = useState(true);
7. 
8.   useEffect(() => {
9.     const storedToken = localStorage.getItem('jwt_token');
10.     const storedUser = localStorage.getItem('user');
11. 
12.     if (storedToken && storedUser) {
13.       setToken(storedToken);
14.       setUser(JSON.parse(storedUser));
15.     }
16.     setIsLoading(false);
17.   }, []);

     Під час ініціалізації виконується перевірка локального сховища браузера для автоматичного відновлення сесії користувача.
     Функції login та logout забезпечують керування життєвим циклом авторизації:
1. const login = (newToken: string, newUser: User) => {
2.   localStorage.setItem('jwt_token', newToken);
3.   localStorage.setItem('user', JSON.stringify(newUser));
4.   setToken(newToken);
5.   setUser(newUser);
6. };
7. 
8. const logout = () => {
9.   localStorage.removeItem('jwt_token');
10.   localStorage.removeItem('user');
11.   setToken(null);
12.   setUser(null);
13. };

     Для забезпечення захищеної навігації між сторінками реалізовано компонент ProtectedRoute, який перевіряє автентифікацію та роль користувача:
1. export const ProtectedRoute = ({ allowedRoles }: ProtectedRouteProps) => {
2.   const { user, isAuthenticated, isLoading } = useAuth();
3. 
4.   if (isLoading) {
5.     return <div>Завантаження...</div>;
6.   }
7. 
8.   if (!isAuthenticated || !user) {
9.     return <Navigate to="/login" replace />;
10.   }
11. 
12.   if (allowedRoles && !allowedRoles.includes(user.role)) {
13.     return <Navigate to="/app" replace />;
14.   }
15. 
16.   return <Outlet />;
17. };
     
     Даний компонент реалізує рольову модель доступу (RBAC), обмежуючи доступ до адміністративних або користувацьких сторінок залежно від прав.
     Взаємодія з серверною частиною здійснюється через централізований HTTP-клієнт Axios. У ньому реалізовано автоматичне додавання JWT-токена до кожного запиту, а також обробку помилки авторизації:
1. const api = axios.create({
2.   baseURL: 'http://localhost:3000/api',
3. });
4. 
5. api.interceptors.request.use((config) => {
6.   const token = localStorage.getItem('jwt_token');
7.   if (token) {
8.     config.headers.Authorization = `Bearer ${token}`;
9.   }
10.   return config;
11. });
12. 
13. api.interceptors.response.use(
14.   (response) => response,
15.   (error) => {
16.     if (error.response && error.response.status === 401) {
17.       localStorage.removeItem('jwt_token');
18.       localStorage.removeItem('user');
19.       window.location.href = '/login';
20.     }
21.     return Promise.reject(error);
22.   }
23. );
24.
     


     4 ВИСНОВКИ
       
     У ході виконання лабораторної роботи було розроблено клієнтську частину системи Smart Lock у вигляді сучасного SPA-застосунку на базі React. Реалізована архітектура забезпечує модульність, масштабованість та чітке розділення відповідальностей між компонентами системи.
     Було впроваджено механізм маршрутизації за допомогою React Router v6, що дозволило організувати навігацію між користувацькою та адміністративною частинами системи. Для контролю доступу реалізовано рольову модель (RBAC) із використанням захищених маршрутів, що забезпечує доступ до функціоналу відповідно до прав користувача.
     Окрему увагу приділено реалізації механізму автентифікації та керування сесією користувача. Використання JWT-токенів у поєднанні з контекстом AuthContext дозволило забезпечити централізоване управління станом авторизації та підтримку автоматичного відновлення сесії.
     Взаємодія з серверною частиною реалізована через Axios із використанням інтерсепторів, що забезпечує автоматичне додавання токена до запитів та обробку помилки неавторизованого доступу. Такий підхід підвищує рівень безпеки та спрощує супровід коду.
     У результаті виконання роботи отримано практичні навички проєктування SPA-архітектури, реалізації механізмів автентифікації, рольового доступу та інтеграції клієнтського застосунку з REST API у межах IoT-системи Smart Lock.
